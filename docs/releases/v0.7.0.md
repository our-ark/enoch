# Enoch v0.7.0

Enoch v0.7.0 expands the reference agent's chat and runtime choices while
strengthening governed conversation, task recovery, and portable identity.
It includes all changes since v0.6.1, including the memory-subject and
Linux PID-reuse fixes.

## Highlights

- Added a Slack chat provider with `.` commands and `!` fallback, inbound
  files, governed outbound attachments, thread-aware delivery, and command
  argument normalization for Slack links. Telegram remains supported.
- Added a Claude runtime provider alongside Codex, account quota inspection,
  and automatic warnings scoped to the active runtime. Claude session and
  weekly limit exhaustion pause work instead of permanently failing it.
- Enabled natural-language requests to invoke registered operations through
  the same governed handlers as explicit commands. Durable action receipts,
  bounded action loops, and daemon fencing prevent blind replay of uncertain
  actions. Code work still runs through managed task workspaces.
- Separated the versioned software body from portable personal `self.json`
  identity, and added checksummed host migration with source fencing, import
  preview, explicit target activation, and continuity verification.
- Added daily IANA-timezone cron schedules, pause, resume, run-now, and show.
  Cron and extension schedules share DST calculations, and cron lifecycle
  changes are coordinated with task admission.
- Added durable workflow reconciliation, confirmed review-publication
  evidence, and continuation of captured work without rerunning completed
  agent execution. Validation repair stays within the original task budget.
- Isolated background services by installation path and delayed model-backed
  startup context until an actual conversation request. Descendant names and
  chat-specific command prefixes remain consistent in system messages.

## Correctness fixes

- New memories default to the generic subject `user`, not a hardcoded person.
  Explicit subjects and existing records are preserved.
- Private-state daemon checks recognize Linux PID reuse when the live
  process explicitly belongs to another `--root`. Missing or unreadable
  procfs and unattributable processes retain conservative liveness behavior.
- Repository tasks no longer treat unconfirmed review publication as success.
  Failed-task guidance distinguishes retry from resuming paused work.
- Existing persisted daily schedule targets are retained until acknowledged;
  shared DST rules apply when calculating subsequent targets.

## Validation

- The 1,023-test core suite includes hermetic workflow and installed-wheel
  integration tests.
- All 143 reference provider and library tests pass independently.
- GitHub Actions runs core and all nine reference provider/library suites on
  Python 3.11, 3.12, 3.13, and 3.14.
- The two-generation full-body descent gate uses Genesis commit
  `61723cd936c6d5f9a9ed163cf00321fc3fb79722`, validates inherited dependencies
  and tests, and retains per-gate evidence in CI artifacts.

## Compatibility and upgrade

- Python 3.11 or newer; reference host integrations support macOS and Linux.
- Workflow API advances from version 3 to 4. Custom workflow engines must
  implement the current contract, including reconciliation and terminal
  evidence recording; see [workflow contracts](../workflows.md).
- Provider-kit advances from `0.7.0` to `0.8.0` relative to the previous
  release. Provider packages remain independently versioned and pinned to
  immutable revisions; their versions do not follow the Enoch release number.
- Application Composition API 1, Profile API 5, Agent Extension API 1,
  Extension Command Result API 1, and Extension Schedule API 1 are unchanged.
- Task queue state advances to schema 15 and cron state to schema 5. Use
  `bin/enoch state migrate --dry-run`, then stop the daemon before applying
  `bin/enoch state migrate`. Migration creates a backup; retain it when
  considering rollback to an older build.
- Host migration requires compatible checkouts at the same body revision and
  separately configured credentials. Bundles contain private state and are
  not encrypted; see [host migration](../host-migration.md).

Credentials, memories, logs, chat identifiers, task state, and instance
configuration remain outside the public source archive and inheritable body.
Publishing this release does not update or restart existing installations.
The frozen CITB and RIPA research snapshots remain unchanged.
