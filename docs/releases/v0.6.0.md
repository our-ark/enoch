# Enoch v0.6.0

Enoch v0.6.0 gives agent extensions durable, structured, and governed ways to
describe work. Extensions can attach domain data and artifacts to tasks,
serialize related work through execution lanes, and declare periodic work
without owning a second scheduler or control plane.

## Highlights

- Added bounded JSON metadata and typed artifact references to extension task
  requests. Both survive queue persistence, retries, reruns, task events, and
  process restarts while preserving extension provenance.
- Added extension execution lanes. Tasks in one lane retain FIFO order across
  pauses and delayed retries, while ready work in other lanes can continue
  according to the selected workflow engine's policy.
- Added the versioned `ExtensionScheduleSpec` API for fixed-rate intervals and
  timezone-aware daily schedules. Extensions declare schedules as part of
  their normal composition rather than creating polling threads.
- Added durable schedule reconciliation, claim and acknowledgement, missed-run
  coalescing, overlap prevention, pause and resume, and idempotent run-now
  controls.
- Routed scheduled extension work through the selected `ExtensionWorkflow`,
  including capability authorization, task provenance, actor attribution,
  execution lanes, structured payloads, and ordinary workflow recovery.
- Added `ExtensionScheduleConformanceMixin` and expanded extension and workflow
  conformance coverage for structured payloads, lane ordering, timezone
  calculation, declaration removal, and restart recovery.
- Added extension schedule state to the private-state manifest and immune-state
  boundary so schedules remain inspectable, recoverable, and excluded from the
  inheritable software body.

## Reliability semantics

- A persisted occurrence claim becomes part of the workflow idempotency key.
  A crash after task enqueue but before schedule acknowledgement therefore
  recovers the same task rather than creating a duplicate.
- Missed periodic targets coalesce into one occurrence. Pending, running, or
  paused work from the same schedule prevents overlapping execution.
- Interval schedules keep fixed-rate UTC anchors. Daily schedules recompute the
  next wall-clock target in their declared IANA timezone, including daylight
  saving transitions.
- Capability denial and pre-enqueue failures remain visible in durable schedule
  status and structured system events.

## Validation

- The 813-test Enoch body suite passes.
- All 72 reference provider and library tests pass independently.
- The Genesis cross-artifact gate creates and validates a fresh descendant from
  the v0.6.0 release candidate.
- GitHub Actions covers Python 3.11, 3.12, 3.13, and 3.14.

## Compatibility

- Python 3.11 or newer.
- `genesis.toml` schema version 1.
- Application Composition API version 1.
- Agent Extension API version 1.
- Extension Command Result API version 1.
- Extension Schedule API version 1.
- Workflow API version 3.
- Profile API version 5.
- Provider-kit `0.7.0`.
- Genesis v0.2.0 or a later compatible build.
- Existing extensions remain compatible. Structured task payloads, lanes, and
  schedules are optional features with explicit workflow capability checks.
- Existing `/cron` and evolve scheduling continue to use their current durable
  state and share the application scheduler thread with extension schedules.
- Extension packages and composition factories are trusted Python code rather
  than sandbox boundaries.

Credentials, memories, logs, chat identifiers, task state, extension state,
schedule state, and instance configuration remain outside both the public
source archive and the inheritable software body.
